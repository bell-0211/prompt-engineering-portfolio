核心项目

01

System Prompt 架构

把身份、优先级、上下文、工具、证据、安全和完成检查拆成可治理模块。

  • 场景按需加载
  • 运行时 Schema 单一事实源
  • 服务端承担授权与脱敏
02

评测契约 Harness

从合成回复执行检查并生成结论，用评分、证据和发布门禁替代预填 verdict。

  • 正常 / 对抗 / 高风险夹具
  • P0/P1 门禁可执行
  • 离线演示，不冒充模型 Benchmark
03

结构化 Agent 契约

用 Schema 与语义校验约束结构、状态和证据引用；公开样例不宣称领域专家能力。

  • 输入输出 Schema
  • evidence_refs 交叉校验
  • 结构化 golden contracts
04

合成 Prompt 迭代

用人工编写的弱基线与修订版解释修改依据，并通过同一组检查展示契约差异。

  • 不冒充真实模型输出
  • 修改理由可追踪
  • 只证明检查逻辑

工程闭环

需求 → 风险分级 → Prompt / Runtime 契约 → 测试夹具 → 执行证据 → 评分与仲裁 → P0/P1 门禁 → 发布决策 → 版本记录

关键判断：内容分描述回答质量，发布门禁判断能否上线。任何注入泄露、危机信号漏检或关键证据缺失，都不能被高平均分抵消。

诚实的能力边界

不虚构线上指标

不把静态校验、离线执行或模型评分写成生产验证与业务增长。

不把 Prompt 当安全边界

授权、敏感参数、日志和脱敏必须由运行时与服务端执行。
